**Preflight first — tier 1 in the tri-method skill.** This command writes a commit and a PR, so run the checks before changing anything: a dirty worktree, a rebase in progress, or the default branch under `branch-pr` all stop the work.

Load the tri-method skill first. Before running anything: verify the task's acceptance criteria are actually met, run the project's tests, and fill the task's Evidence section with the exact commands and observed results (strict profile: also write tri/evidence/<ID>-<date>.md). Then run `node ${CLAUDE_PLUGIN_ROOT}/scripts/tri.mjs validate` and `node ${CLAUDE_PLUGIN_ROOT}/scripts/tri.mjs done $1`. If either fails, fix the cause — never weaken a gate. `done` warns when a dependency is `Withdrawn` (it does not block — the dependency will never complete) and warns when recorded evidence runtime differs from the configured expected environment; treat both as review prompts, not silent passes. Commit with the task ID in the message and **push it immediately**, verifying the remote ref matches the local commit. A push failure stops. In branch-pr workflow, ask whether to open a PR against configured development base, and separately ask before merging it; never assume merge or merge silently. Changes touching contracts/shared files require the other dev's review.
