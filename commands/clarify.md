description: Interrogate and refine what is unclear — a task, a phase, a plan, or a decision — then write the results into the task files and registers

**Preflight first — tier 1 and 2 in the tri-method skill.** This command writes register entries and task edits, so run the checks before changing anything: a dirty worktree, a rebase in progress, or the default branch under `branch-pr` all stop the work, and a stale ref means the identifier you allocate may already be taken.

Load the tri-method skill first. Run `node ${CLAUDE_PLUGIN_ROOT}/scripts/tri.mjs next` and `status`; if $ARGUMENTS names a task or phase, focus there, otherwise present the ready frontier and upcoming phases so the user sees exactly what's next. **Match depth to the target.** A task or phase with vague specifications: batch the questions, up to four per call, and move fast. A plan, an architectural direction, or a decision the user is unsure about: interrogate **one question at a time**, hardest assumption first, because each answer reshapes the next — that is the mode to use whenever the user expresses doubt or asks you to poke holes.

Then surface what is ambiguous, underspecified, or contradictory — scope edges, acceptance criteria that aren't binary, missing dependencies, dependencies that look ceremonial. **Put each real decision to the user with AskUserQuestion** (recommended option first, marked; tradeoff in every description; batch up to four independent ones per call). Reserve prose for genuinely open-ended wording.

When the user answers, apply the edits to the task files (Objective, In/Out of scope, Acceptance criteria, Dependencies — use `new-task` for work that turns out to be separate, never scope-fold). Record decisions/assumptions in the registers as in the tri-method skill. Finish with `validate` and a diff-style summary of every task changed. Then **continue**: if a clarified task is now ready and the user's ask implied working on it, claim and start it; if the clarification produced an architectural decision, write that ADR; if it produced a queue of ready work, offer the batch. Do not end by naming a command.
